# API 명세서

## 1. 공통 규칙

- Base URL: /api
- 데이터 형식: JSON
- 금액 및 포인트 단위: 정수
- 포인트 충전 비율: 1원 = 1포인트

## 2. 커피 메뉴 조회

### 기본 정보

- Method: GET
- URL: /api/menus
- 설명: 등록된 커피 메뉴 목록을 조회한다.

### 성공 응답: 200 OK

[
  {
    "menuId": 1,
    "name": "아메리카노",
    "price": 4000
  },
  {
    "menuId": 2,
    "name": "카페라떼",
    "price": 4500
  }
]

### 처리 규칙

- 메뉴 ID, 메뉴명, 가격을 반환한다.
- 등록된 메뉴가 없으면 빈 배열을 반환한다.

## 3. 포인트 충전

### 기본 정보

- Method: POST
- URL: /api/points/charge
- 설명: 사용자의 포인트를 충전한다.

### 요청 예시

{
  "userId": "user-1001",
  "amount": 10000
}

### 성공 응답: 200 OK

{
  "userId": "user-1001",
  "chargedAmount": 10000,
  "balance": 10000
}

### 처리 규칙

- userId는 필수이며 공백일 수 없다.
- amount는 0보다 큰 정수여야 한다.
- 1원 충전 시 1포인트를 적립한다.
- 최초 충전 시 해당 사용자의 포인트 계정을 생성한다.
- 기존 계정이 있으면 기존 잔액에 충전 금액을 더한다.
- 충전 내역과 잔액 변경은 함께 처리한다.

## 4. 커피 주문 및 결제

### 기본 정보

- Method: POST
- URL: /api/orders
- 설명: 커피 주문을 생성하고 포인트로 결제한다.

### 요청 예시

{
  "userId": "user-1001",
  "menuId": 1
}

### 성공 응답: 201 Created

{
  "orderId": 101,
  "userId": "user-1001",
  "menuId": 1,
  "menuName": "아메리카노",
  "paidAmount": 4000,
  "remainingPoint": 6000,
  "status": "PAID"
}

### 처리 규칙

- userId와 menuId는 필수이다.
- 존재하는 메뉴만 주문할 수 있다.
- 포인트 계정이 존재해야 결제할 수 있다.
- 잔액이 메뉴 가격보다 적으면 결제에 실패한다.
- 결제 성공 시 포인트를 차감한다.
- 주문 생성, 포인트 차감, 포인트 사용 내역 저장은 하나의 트랜잭션으로 처리한다.
- 주문 당시 가격을 주문 데이터에 저장한다.
- 결제 완료 정보를 데이터 수집 플랫폼으로 전달할 이벤트를 저장한다.

## 5. 인기 메뉴 조회

### 기본 정보

- Method: GET
- URL: /api/menus/popular
- 설명: 최근 7일간 인기 메뉴 최대 3개를 조회한다.

### 성공 응답: 200 OK

[
  {
    "menuId": 1,
    "name": "아메리카노",
    "orderCount": 120
  },
  {
    "menuId": 2,
    "name": "카페라떼",
    "orderCount": 95
  }
]

### 처리 규칙

- 조회 시점을 기준으로 직전 7일 동안의 주문을 집계한다.
- 결제가 성공한 주문만 집계한다.
- 메뉴별 주문 건수를 계산한다.
- 주문 건수가 많은 순서로 정렬한다.
- 주문 건수가 같으면 menuId 오름차순으로 정렬한다.
- 결과는 최대 3개이다.
- 주문이 없는 메뉴는 집계 결과에서 제외한다.

## 6. 오류 코드 및 오류 응답

### 6.1 오류 코드 규칙

오류 코드는 기능별 접두어와 일련번호를 조합한다.

* `COMMON`: 공통 오류
* `MENU`: 메뉴 관련 오류
* `POINT`: 포인트 관련 오류
* `ORDER`: 주문 관련 오류

오류 코드는 API 응답, 로그, 테스트에서 동일하게 사용한다.

### 6.2 오류 코드 목록

| 오류 코드      | HTTP 상태 코드 | 오류명                        | 설명                      |
| ---------- | ---------- | -------------------------- | ----------------------- |
| COMMON_001 | 400        | INVALID_REQUEST            | 잘못된 요청입니다.              |
| COMMON_002 | 500        | INTERNAL_SERVER_ERROR      | 서버 내부 오류가 발생했습니다.       |
| MENU_001   | 404        | MENU_NOT_FOUND             | 메뉴를 찾을 수 없습니다.          |
| POINT_001  | 400        | INVALID_CHARGE_AMOUNT      | 충전 금액은 0보다 커야 합니다.      |
| POINT_002  | 404        | POINT_ACCOUNT_NOT_FOUND    | 포인트 계정을 찾을 수 없습니다.      |
| POINT_003  | 409        | INSUFFICIENT_POINT         | 포인트 잔액이 부족합니다.          |
| POINT_004  | 409        | CONCURRENT_UPDATE_CONFLICT | 동시성 문제로 요청을 처리하지 못했습니다. |
| ORDER_001  | 400        | INVALID_ORDER_REQUEST      | 주문 요청 정보가 올바르지 않습니다.    |

### 6.3 오류 응답 형식

모든 API 오류 응답은 다음 형식을 사용한다.

```json
{
  "code": "POINT_003",
  "message": "포인트 잔액이 부족합니다."
}
```

* `code`: 오류를 식별하는 고유 코드
* `message`: 오류 상황을 설명하는 메시지

### 6.4 오류 처리 원칙

* 요청 데이터의 형식이나 필수 값이 잘못되면 400 응답을 반환한다.
* 존재하지 않는 메뉴나 포인트 계정을 조회하면 404 응답을 반환한다.
* 포인트 잔액 부족으로 결제할 수 없으면 409 응답을 반환한다.
* 동시성 충돌이 발생해 요청을 처리하지 못하면 상황에 따라 409 응답을 반환할 수 있다.
* 예상하지 못한 서버 내부 오류는 500 응답으로 처리한다.
* 오류 코드와 HTTP 상태 코드는 실제 구현 및 테스트와 일치시킨다.


## 7. 설계 시 추가 검토 사항

- 여러 서버에서 동시에 충전하거나 결제할 때 잔액의 정합성을 보장한다.
- 동시에 최초 충전 요청이 들어오는 경우에도 계정이 중복 생성되지 않도록 한다.
- 주문과 포인트 변경은 원자적으로 처리한다.
- 외부 데이터 수집 플랫폼 전송 실패에 대비해 재시도할 수 있도록 설계한다.
- 외부 전송 이벤트가 중복 처리될 가능성을 고려한다.
- API 오류 상황과 동시성 상황을 테스트한다.
